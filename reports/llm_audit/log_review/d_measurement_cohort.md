## 4. 부산물 발견 — 가설 뒤집힘 3건

### 4.1 "틈새 가설" 폐기

이전 가설 ("2021·2025·2016이 노드 구간 밖이라 graph=0 또는 오매칭") **틀림**. graph 노드 실존:
- 2021 → `grad_2021_내국인`, `grad_2021_외국인`, `method_방법1_2021`, `method_방법2_2021`
- 2025 → `2024_2025` 그룹에 포함
- 2016 → `grad_2016_before_내국인`

### 4.2 `query_analyzer` 학번→그룹 매핑이 graph 노드 구조와 1:1 일치

```
2020 → 2017_2020 그룹
2024 → 2024_2025 그룹
2016 → 2016_before
2021 → 2021 (단독)
```

이건 의도된 정상 동작. 우리가 "#3 query 확장" 의심한 건 사실 정확한 그룹 매핑.

### 4.3 #2 / #3 가설 — **다른 현상** (한 뿌리 아님)

- **#2** "2024 → 2023이후" 매칭 = 의도된 범위 그룹화 (정합)
- **#3** "2024 → 2024_2025" 매핑 = 정확한 학번→그룹 lookup (정합)

둘 다 cohort 경계 느슨함 아닌 **정상 그룹화**. 한 뿌리로 묶을 필요 없음.

## 5. ⚠️ 미해결 — range/bound 표현 (B 측정 후 약점 인정 여부 결정)

본 측정에서 발견된 현상:

| 쿼리 | 의도 | 실제 매칭 |
|---|---|---|
| "2020학번 이후" | 2020~2025 전체 그룹 (5+ 그룹) | 2017_2020 그룹 하나 (과거 한정) |
| "2020~2024학번" | 2017_2020, 2021, 2023, 2024_2025 (4 그룹) | 2024_2025 한 그룹만 |

`query_analyzer`는 양쪽 그룹을 정확히 추출 (`query_cohort=2017_2020,2024_2025`). graph_search 단계에서 한쪽만 매칭됨.

**다만 이게 "진짜 약점(버그)"인지 "드문 표현이라 영향 없음"인지는 아직 모름**. 운영 트래픽에서 range/bound 표현으로 졸업요건 묻는 비중을 측정해야 함. 일반적으로 학생은 자기 학번 하나로 묻지 범위로 묻지 않음.

→ **B 측정 (운영 로그에서 range/bound 비중) 결과 보고 A 작업 필요성 결정**.

## 6. 위험 위치 재추적

```
1주차 진단:
  direct_answer 위험 16% → grounding 부적합 (범주 오류, 측정으로 확정)
  → "retrieval 정합성"으로 이관 (cohort 매칭 정확성이 핵심으로 추정됨)

2주차 D 측정 (본 보고서):
  cohort 오매칭 위험 (졸업학점 계열) = 0% (확정)
  cohort 커버리지 구멍 = 0% (확정)
  → cohort 정합성 위험 = 졸업학점 계열에서 해소
  → 미해결: method_* 타입, range/bound 표현, 운영 비중

남은 direct_answer 안전성 위험:
  cohort 매칭이 아니라 PR #25 게이트 자체로 좁혀짐.
  "어떤 노드를 direct_answer로 채택할지" (rerank logit ≥ 0.20)가 진짜 결정 지점.
  → 다음 작업 = D+B 묶음 (logit 분포 + range 비중 동시)
```

위험 범위가 **1주차 진단 대비 다시 한 번 축소**. 1주차 grounding 종료와 같은 종류의 결말 — "측정 후 진짜 위험이 더 좁아짐".
